# 无障碍人工审计协作工作台

源提示词摘要：审计员记录问题、复现步骤、影响人群和严重程度，审核员判断重复或补充证据，开发人员提交修复，复测人员关闭或重新打开问题；所有核心流程可以用键盘完成，并正确管理焦点和错误提示。

## 协作数据模型（同一份可恢复数据）

问题单、处理记录、合并关系不再分散存储，而是同一份版本化协作文档（`src/lib/collab.ts` 的 `CollabDoc`）：

- `issues`：问题单，带修订号 `rev`，工作流字段为 `status / fixNote / retestNote`。
- `records`：处理记录（只追加），与问题单在**同一次文档写入**中落盘。
- `mergeLinks`：合并关系 `被合并单 -> 父单`，经 `resolveRoot` 总能解析到最终问题单，`compressLinks` 做路径压缩——无论经过几层（甲→乙→丙…），旧链接都直接指向最终单。
- `conflicts`：保存前比对产生的冲突，双方修订两份都保留，审核员逐字段选定。

### 保存前比较双方修订

保存操作携带打开时的旧版本快照（三方比对的 base）。提交时逐字段判定：

- 对方没动、我改了：我的修订成立；
- 对方改了、我没动：接受对方修订；
- 双方改成同值：自然合并；
- **双方都基于旧版本改了同一字段且结果不同：两份都留下**（`FieldCandidates.mine/theirs`），头部暂保留对方值，生成未解决冲突。

不同字段的并发修订自动合并。

### 未选定不能关闭

- 试图把状态保存为 `closed` 时，只要该问题单存在未选定冲突，关闭动作本身也会进入冲突裁定且不落为 `closed`。
- 冲突必须**逐字段**在「冲突裁定」面板单选我方/对方修订，全部选定后才生成一条 `conflict-resolution` 处理记录并与问题单一起写入。
- 尚有其他未解决冲突时，裁定提交也会被拒绝。

### 问题单与处理记录一起写入（WAL）

所有变更（新建 / 保存 / 合并 / 裁定）先写入 WAL 待办日志，再一次性提交文档：

- 文档保存失败（如配额/存储异常）时，**问题单与处理记录都保留原值**，操作留在 WAL，界面顶部出现「待写入操作」面板，可立即重试或放弃。
- **重开后自动续传恰好一次**：先把条目标记 `resumed` 再提交，即使提交中崩溃也不会再自动续；之后只能人工重试。
- 重放幂等：处理记录以操作 `opId` 去重，崩溃恢复不会产生重复记录。
- 校验失败（如未选全冲突字段）的操作不写文档、带错误原因留在 WAL。

### 合并关系始终回到最终问题单

- 挂接时按根节点合并并即时路径压缩；多层旧链路（种子数据含 `issue-4 → issue-3 → issue-2`）读取时也会压缩为直达最终单。
- 环会被检测并拒绝；重复合并到同一最终单幂等跳过。

## 并发演练

- **两个浏览器标签页**：直接同时编辑即可，`storage` 事件会让另一页重新装载同一份文档并提示基线已落后。
- **单页模拟**：问题详情下方「协作演练工具」可模拟其他审核员先保存（制造头部新版本）、模拟不同字段自动合并、模拟下一次写入失败。随后基于旧版本点状态按钮即可复现冲突双份留存与关闭护栏。

## 技术栈

SolidStart、TypeScript、Ark UI、Solid Router、Solid Store、Modular Forms、Zod、Solid i18n primitives。协作逻辑为框架无关纯函数，带独立测试。

## 本地运行

```bash
npm install
npm test     # 协作数据层 11 个测试：冲突、关闭护栏、原子写失败/续传、幂等、多层合并
npm run dev  # 端口 62025
```

数据保存在 localStorage：文档键 `a11y-audit-collab-v2`，WAL 键 `a11y-audit-collab-v2-wal`；旧版 `a11y-audit-v1` 首次打开时自动迁移。

## 无障碍

支持跳过导航、可见焦点、`role="alert"/"status"` 提示、冲突单选钮键盘操作、`Ctrl+Enter` 提交；冲突与写入失败均有明确、可感知的反馈。
